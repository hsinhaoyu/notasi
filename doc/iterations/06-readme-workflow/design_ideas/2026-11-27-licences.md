# Design idea: licences

Status: agreed in discussion (2026-11-27). Not the design until
promoted.

## The problem

notasi has no licence, so no one may legally use, copy or change it.
The project holds two kinds of work: code, and content (the manual,
the examples and their drawings). Software licences fit code;
Creative Commons licences fit content, and Creative Commons itself
advises against them for software. Some examples are transcriptions
from published books, which aren't the user's to license, and
`examples/contrib/` is meant to hold other people's files.

## Settled (2026-11-27)

| Part | Licence | Credit goes to |
|---|---|---|
| The code: everything not listed below | MIT, in `LICENSE` at the top of the repository | the user |
| The user manual, `doc/manual/` | CC BY 4.0, in `doc/manual/LICENSE` | the user |
| `examples/` (gallery, demos, manual, and their images) | CC BY 4.0, in `examples/LICENSE` | the user, except the published transcriptions it names |
| `examples/contrib/` | CC BY 4.0, covered by `examples/LICENSE` | each file's contributor |

- **GitHub** reads the top-level `LICENSE` and shows "MIT license" on
  the repository page. A `LICENSE` in a folder covers that folder;
  GitHub doesn't show it on the main page, which is fine.
- **Published transcriptions.** `examples/LICENSE` names the files
  whose notes come from a published source (Gold's Jaya Semara,
  Tenzer's Baris, and any others), says the user licenses only their
  own work in them (the encoding as a notasi file, the comments), and
  that the source keeps its rights. Each such file already names its
  source with `:source`.
- **Contributions to `examples/contrib/`.** Inbound licence equals
  outbound: contributors keep the copyright and license their files
  under CC BY 4.0. `examples/LICENSE` and `CONTRIBUTING.md` say once:
  "By adding a file to `examples/contrib/`, you license it under
  CC BY 4.0 and confirm you have the right to: it's your own
  transcription or composition, or its source allows it." Opening the
  PR is the agreement. No CLA, no signed commits.
- **Credit in contributed files** uses the piece information keys
  `:contributor`, `:transcriber` and `:source` (01, 07), so the
  CC BY credit is in the file itself. A file without them is asked
  about before it is merged. `contrib/` stays untested (07), so this
  is a review rule, not a test.
- **The README** ends with a "Licence" section, the user's: one or two
  sentences saying the code is MIT and the manual and examples are
  CC BY 4.0, linking to the three files.
- **Releases.** `examples/` and `doc/manual/` reach `main` with their
  `LICENSE` files; `/release` copies them like any other file.

Not a lawyer's advice: if the published transcriptions matter, the
user asks their authors.

## Notes for promotion

`07-environment.md` already describes `examples/` and how
