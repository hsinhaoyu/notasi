# Design idea: mistakes shown in the text

Status: proposed in discussion (2026-11-24). Not the design until
promoted.

## The idea

When the notation has a mistake, `notasi render` exits with status 1
and prints `FILE:LINE: message`, e.g.
`jaya-semara.nts:21: part 'ugal', pulse 2: 'o9' is not a note of
instrument 'ugal'`.

The mode shows it the way Emacs users already know:

- **Through Flymake.** The mode is a Flymake backend: the line is
  marked, the message shows when the cursor is on it, and
  `M-x flymake-goto-next-error` and the mode line's error count work.
- **The picture stays.** The preview keeps the last good drawing, so
  the user doesn't lose their place while fixing a mistake.
- **The preview's header line turns red** and shows the message, so a
  user looking only at the picture still sees why it didn't change.
- **Fixing the mistake** clears the mark and the red header, and the
  picture updates.

Other failures (Guile or Typst missing, notasi not found, Typst
failing) are not mistakes in the notation. They are shown once, as a
plain sentence in the preview, saying what is missing and pointing to
the manual. They are not repeated on every redraw.

## Open

- notasi stops at the first mistake, so only one is ever marked.
  Collecting several would be a change to the reader. Suggested: one
  is enough for this iteration.
- Some messages name a line but not a column. Flymake marks the whole
  line then. Fine?
- A mistake in a template (`(use gong-kebyar)`) names the template's
  file. Suggested: mark the `(use …)` line, with the message.
- notasi's messages and their format become something the mode
  depends on. That should be written down as a contract
  (05-typst-backend), so changing it means changing the mode.
