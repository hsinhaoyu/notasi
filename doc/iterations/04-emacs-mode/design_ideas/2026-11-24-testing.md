# Design idea: testing the mode

Status: agreed in discussion (2026-11-24); see "Settled". Not the
design until promoted.

## The idea

- **ERT tests** in `editors/emacs/notasi-mode-tests.el`, run with
  `emacs -Q --batch`, so they don't depend on anyone's configuration.
- **A fake notasi** (`editors/emacs/fake-notasi`): a short script
  that writes a tiny SVG to the `-o` file, or, if the input contains
  `MISTAKE`, prints `FILE:3: a mistake` and exits 1. The tests use it,
  so they need neither Guile nor Typst and run fast.
- **One real test** draws `examples/jaya-semara.nts` with the real
  `scripts/notasi`, skipped when Guile or Typst is missing.
- **`make check-emacs`** runs the tests, byte-compiles with warnings
  as errors, and runs `checkdoc` and `package-lint`. It is separate
  from `make check`, because not everyone working on notasi has
  Emacs.
- **CI** runs `make check-emacs` in its own job, on the oldest and the
  newest Emacs the package supports.
- **Written first**, as for every milestone: `/start-milestone` writes
  the tests from the design document before the code.

## Open

- What is tested in batch mode is the logic: finding scores, finding
  notasi, reading errors, cleaning up. How the preview window looks
  can't be. Suggested: those are checked by hand, with a short
  checklist in the milestone's PR.
- `package-lint` comes from MELPA; CI has to install it. Fine?

## Settled (2026-11-24)

- **Batch tests** cover the logic. How the preview looks is checked by
  hand, from a short checklist in each milestone's PR.
- **`package-lint`**: CI installs it from MELPA.
