# Design idea: how a drawing is made

Status: proposed in discussion (2026-11-24). Not the design until
promoted.

## The idea

The package draws only by calling the `notasi` command:

    notasi render FILE.nts [--score NAME] -o OUT.svg

It doesn't load or depend on anything in `notasi/` directly. Every
step below is hidden from the user.

- **Unsaved text.** The mode writes the buffer's text to a hidden
  temporary file *in the same folder* as the `.nts` file
  (`.notasi-preview-NAME.nts`), so `(use …)` and local files are found
  the same way as for the real file. It draws that, then deletes it.
  In messages, the temporary file's name is replaced with the real one.
  `.gitignore` gets `.notasi-preview-*`.
- **Output** goes to a temporary folder made for the buffer, never
  beside the user's file.
- **SVG**, so the picture stays sharp at any size. If this Emacs can't
  show SVG, PNG.
- **In the background** (`make-process`), so Emacs never freezes. If a
  drawing is running when a new one is needed, the old one is stopped.
- **Fresh pictures.** The image is reloaded from its file every time,
  so Emacs's image cache never shows an old one.

## Open

- **Speed.** Each drawing starts Guile and Typst from scratch, and
  `scripts/notasi` runs with `--no-auto-compile`. Nobody has timed it.
  Time `jaya-semara.nts` before promotion. If it takes more than a
  second or two, options are: compiling notasi's modules ahead of
  time; a `notasi serve` process that stays running and draws on
  request; or only redrawing on save. Each is a change to notasi, not
  only to the mode.
- **The hidden file beside the user's file** could be seen by other
  tools watching the folder (e.g. Dropbox, `typst watch`). The
  alternative is a temporary file elsewhere plus a way to tell notasi
  where to look for local files (`--base-dir`?), which is a change to
  notasi. Suggested: the hidden file, and see if it bothers anyone.
