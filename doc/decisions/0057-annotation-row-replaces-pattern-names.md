# 0057 An annotation row shows one part's pattern names, annotations and free text; `:pattern-names` is removed

Status: accepted (2026-11-26)

Context: `:pattern-names short/long` writes pattern names over the notes, as overlays across all the group's rows, merged from every part of the group, at one level of nesting (`:pattern-level`). Overlays cover the music they name, and names from different parts can clash, which is an error. A writer may also want to say more than a name ("norot on 1") or mark a moment in the music ("angsel") that is not a pattern.

Decision: A group can have one annotation row, above or below its rows: text only, with no background and no notes, taken from one part of the group (`:annotation-part`). It shows the names of that part's patterns at one level of nesting (`:annotation-level`), each across its use, short, long or the pattern's annotation (`:annotation-text`, default `annotation`, falling back to the long name), aligned left, centre or right; text longer than its span is cut, left-aligned. All its options start `:annotation-` and are set on a group only. A pattern carries an annotation with `:annotation STRING`, and a use can replace it. Free text is written in the part, where it happens, as `(text STRING)` or `(text STRING LENGTH)`, a token that takes no time; it is shown only in an annotation row taken from that part, and wins over pattern text where they overlap. `:pattern-names`, `:pattern-level`, their overlays and the error for clashing names are removed, with no migration.

Consequences: Pattern names never cover notes, and nothing needs merging. Jaya Semara's `kotekan` score moves its names to an annotation row from polos. The piece records pattern annotations and text events (02); the JSON loses each group's `overlays` and gains its annotation row in contract version 4 (05), which narrows ADR 0043; the template draws the row. `text` becomes a reserved list head.
